## Root cause
The `<Button>` used at `app/cv/page.tsx:21` is being type-checked against the prop type `IntrinsicAttributes & RefAttributes<any>` — a signature that declares **no component props at all** (no `children`, `variant`, `size`, or `asChild`). That means the `Button` symbol in scope is **not** the fully-typed shadcn/ui Button; its declared props collapsed to a bare `forwardRef` with `any`, so passing `children`/`variant`/`size`/`asChild` is rejected.

Most likely origin (to be confirmed by E1 reading the files — eph sandbox could NOT be spawned to verify, so this is inferred from the compiler output, not reproduced):
- `components/ui/button.tsx` is missing a proper `ButtonProps` type (should extend `React.ButtonHTMLAttributes<HTMLButtonElement>` + `VariantProps<typeof buttonVariants>` + `{ asChild?: boolean }`), and/or the `forwardRef` is typed as `forwardRef<any>` without a props generic — so the exported `Button` carries no props type.
- Or `app/cv/page.tsx` imports `Button` from the wrong module (not `@/components/ui/button`), resolving to a bare-typed component.

## Suggested fix (Code — E1)
In `components/ui/button.tsx`, restore the typed props and forwardRef generics, e.g.:
```tsx
export interface ButtonProps
  extends React.ButtonHTMLAttributes<HTMLButtonElement>,
    VariantProps<typeof buttonVariants> {
  asChild?: boolean
}

const Button = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ className, variant, size, asChild = false, ...props }, ref) => {
    const Comp = asChild ? Slot : "button"
    return <Comp className={cn(buttonVariants({ variant, size, className }))} ref={ref} {...props} />
  }
)
Button.displayName = "Button"
```
Then confirm `app/cv/page.tsx` imports it via `import { Button } from "@/components/ui/button"`. After the fix, `yarn build` / `next build` should pass the type-check.
